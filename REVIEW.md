# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33-37) | Timezone mixing and off-by-one grace threshold. `minutes > 10` returns 0 for 10m 01s (601s) because `int(601/60) = 10`, failing `> 10`. Also, naive `punch_in.replace(...)` mixes UTC with local/IST time and fails overnight shifts. | Punch-in at 09:40:01 for a 09:30 shift returns `late_minutes = 0` instead of `10` as mandated by R2. | Converted `punch_in` to IST, compared elapsed seconds strictly against 600 (`delta_sec > 600`), and took `math.floor(delta_sec / 60)`. |
| 2 | `compute_overtime` (lines 44-47) | Awards overtime for any positive duration without enforcing the 30-minute threshold (R3). Does not handle overnight shifts crossing midnight into next day. | Punching out 10 minutes after shift end gives `10` instead of `0`. | Checked if `shift_end <= shift_start` (overnight) to anchor shift end to next calendar day; only award overtime if `ot_min >= 30`, returning 0 otherwise. |
| 3 | `compute_work_hours` (lines 40-41) | Uses Python built-in `round()`, which applies Banker's rounding (round half to even) rather than round half-up (R4/R8). | A duration resulting in `.125` rounds to `.12` instead of `.13`. | Implemented `Decimal` rounding with `ROUND_HALF_UP` quantized to 2 decimal places. |
| 4 | `health` (lines 72-74) | Returns `{"status": "ok"}` 200 unconditionally without verifying MongoDB connectivity. | Stopping MongoDB still returns 200 instead of 503 Service Unavailable. | Executed `client.admin.command('ping')` in a try/except block; raised `HTTPException(503)` on failure. |
| 5 | `create_employee` (lines 77-85) | Check-then-insert race condition (`find_one` then `insert_one`) allows duplicate `emp_code` or raises unhandled 500 errors. | Concurrent `POST /employees` requests with identical `emp_code` result in race conditions or 500 errors. | Created unique index on `emp_code` at startup; caught PyMongo `DuplicateKeyError` and raised 409 Conflict. |
| 6 | `EmployeeIn` model (lines 53-60) | Missing validation: does not ensure `shift_start != shift_end`, no regex for `emp_code` format (`^EMP\d{4,6}$`), and sets `created_at` using local time. | Creating an employee with `shift_start == shift_end` succeeds instead of returning 422. | Added Pydantic field validators and regex patterns enforcing `shift_start != shift_end` and `EMP\d{4,6}`, raising 422 on invalid input. |
| 7 | `list_employees` (lines 88-96) | Offset calculation bug: `skip = page * page_size` skips the first page when `page=1`. `total` counts entire collection ignoring `department` filter, and sorting is missing. | `GET /employees?page=1` omits items 1-20. Department filtering shows total company headcount. Items are not sorted by `emp_code`. | Set `skip = (page - 1) * page_size`, used `count_documents(q)` to reflect filter, and sorted by `emp_code` ascending. |
| 8 | `punch_in` (lines 99-122) | Check-then-insert concurrency race condition allows duplicate punch-ins for the same employee and date. | Concurrent requests for the same employee and date both succeed with 201 Created. | Enforced compound unique index on `("emp_code", 1), ("date", 1)`; caught `DuplicateKeyError` and raised 409 Conflict. |
| 9 | `punch_in` date & truncation (lines 102-104) | Uses `datetime.fromtimestamp(...)` producing naive local datetimes, fails to truncate instants to whole seconds (R1), and ignores overnight shift date logic (R1). | Punch-in at 05:30 IST for an overnight shift (22:00 - 06:00) assigns today's date instead of yesterday's shift date. Milliseconds are not truncated. | Truncated instants to whole seconds `(ms // 1000) * 1000`, converted to UTC BSON datetime, and derived attendance date in IST applying overnight rules. |
| 10 | `punch_in` response (line 119) | Injects `id: str(res.inserted_id)` into response, violating the OpenAPI schema which disallows `id` and `_id`. | OpenAPI schema validation fails on unexpected property `id`. | Removed `id` field from response and formatted document to match `AttendanceRecord` schema. |
| 11 | `list_attendance` (lines 124-150) | Loads entire collection into memory (`list(db.attendance_logs.find(q))`) and sorts in Python. Injects `id: str(d.pop("_id"))`. | Server runs out of memory and times out on 100k records. Extra `id` field violates contract. | Moved sorting and pagination directly to MongoDB using `.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)`, and removed `id`. |
| 12 | Missing startup index creation | Starter creates no indexes at startup, leading to full collection scans (`COLLSCAN`) across all endpoints. | Explain endpoint tests show `COLLSCAN` on 100k datasets. | Added FastAPI `lifespan` handler to idempotently create all required unique and compound indexes at startup. |

### Things examined and decided NOT to be defects
- **Instant format difference across boundaries:** The API accepts and returns integer epoch milliseconds while MongoDB stores them as BSON datetimes (UTC). This was verified as an explicit requirement in `DATA_MODEL.md` (instants in MongoDB are UTC BSON dates; in the HTTP contract they are epoch milliseconds).
- **Absence of `id` on attendance records:** Attendance records have no MongoDB `_id` exposed in the API; they are naturally keyed by `(emp_code, date)`. This is strictly by design per `openapi.yaml`.
